# NTM 与持续学习结合：初步研究结论

## 一句话结论

这个方向值得继续，但不建议第一版就“用 NTM 擦除/添加完整 adapter 参数”。更稳妥、
更容易形成可信论文的起点是：

> 把少量低秩 adapter bases 作为固定容量的连续参数记忆，用输入相关的内容寻址产生
> signed sparse composition；在此基础上，再把 NTM 式可写机制作为第二个独立变量，
> 检验何时应该 allocate、write 或 no-write。

这样可以把两个问题分开：

1. 连续读取/组合历史专家是否有效？
2. 修改已经占用的专家记忆是否安全且有必要？

如果一开始把 latent decoder、读写头、动态分配、双层路由全部放在一个模型里，即使性能
提高，也很难判断收益来自额外参数、额外计算、软组合、路由还是写入。

## 与 CaRE 的关系

参考论文 CaRE 的核心是每个 ViT block 中的双层路由：

1. class perceptrons 选择 Top-M task-specific routers；
2. 每个 router 再选择 Top-K historical adapter experts；
3. 同时始终启用一个 EMA shared expert。

CaRE 默认使用 M=2、K=3，并在 ViT-B/16-IN21K 上评估常规 5–20 task 和
OmniBenchmark-1K 的 100–301 task 长序列。

CaRE 是最重要的直接比较对象，但它不是 NTM 式可写记忆。建议同时提供：

- 官方或尽可能严格的 CaRE 结果；
- 参数量、active experts 和 FLOPs 匹配的 CaRE-inspired bi-level router；
- flat content router；
- task-ID/class-aware oracle 只作为含标签泄漏风险的上界；
- label-free prototype oracle 作为更可信的路由机会诊断。

## 建议的主方法

### 方法 A：Signed Top-2 Basis Memory

在选定的 ViT blocks 中保存少量低秩 adapter bases：

\[
\mathcal{B}_l=\{(k_{l,i}, A_{l,i}, B_{l,i})\}_{i=1}^{S}.
\]

对输入表示产生 query：

\[
q_l=f_q(h_l^{CLS}).
\]

根据 query 与 keys 的相似度选择绝对值最大的两个槽，并保留系数符号：

\[
I_l=\operatorname{TopK}_{i}(|s_{l,i}|,2),\qquad
\alpha_{l,i}=
\frac{s_{l,i}}{\sum_{j\in I_l}|s_{l,j}|+\epsilon}.
\]

组合出的低秩更新为：

\[
\Delta W_l(x)=
\sum_{i\in I_l}\alpha_{l,i}B_{l,i}A_{l,i}.
\]

它与普通方法的区别：

- 不是 Top-1 完整 adapter；
- 不是对所有 experts 的 dense softmax；
- 不是每任务增加一个模块；
- 同一组 bases 可以跨任务形成不同的 signed composition。

第一版先让 bases 可训练但固定容量，不做 NTM erase/add。这样可以先验证“连续参数记忆
读取”本身是否有效。

### 方法 B：Bounded Damage-Aware Allocate-or-Write

第二阶段再研究写入。不要只用 embedding novelty 决定是否覆盖，因为“看起来相似”不代表
梯度更新安全，“看起来新颖”也不一定会破坏旧知识。

建议用旧类 prototypes 或低秩 gradient sketches 估计候选写入导致的旧知识损伤：

\[
\hat d_i=\langle g_{\text{new},i}, P_{\text{old},i}g_{\text{new},i}\rangle.
\]

决策规则：

- 有空槽且预计损伤高：allocate；
- 无空槽或预计损伤低：选择预计损伤最小的合法槽；
- 写入超过安全界：reject/no-write；
- erase gate、add norm 和累计 slot drift 都有硬上界；
- 写入使用事务式更新，出现 NaN 或超界时回滚。

这个方法必须与以下对照比较：

- nearest-slot always write；
- cosine novelty allocate-or-write；
- append-only memory；
- allocate-then-freeze；
- frozen old slots；
- 完全 no-write。

如果 no-write 最终更好，应把它作为有价值的负面结论，而不是继续堆写入正则。

## 最重要的四条可证伪假设

1. 在统一 classifier calibration 后，memory 方法的优势可能明显缩小；basis memory
   应在容量饱和或任务交错时才显现优势。
2. 预计写入损伤可能比 embedding novelty 更适合决定 allocate/write，但修改旧槽本身
   也可能始终不如冻结。
3. route hysteresis 应降低旧样本路由切换；若切换减少但准确率不变，则路由稳定不是
   遗忘的因果来源。
4. CaRE 式层级路由可能只对“大而稳定的冻结 expert bank + 清晰任务边界”有利；
   writable memory 或 boundary-free stream 中 flat routing 可能更可靠。

## Baselines

### 直接机制对照

- calibrated frozen ViT + normalized nearest-class-mean；
- single shared adapter；
- hard Top-1 adapter；
- hard Top-K adapter mixture；
- dense softmax adapter mixture；
- append-only key-value adapter memory；
- allocate-then-freeze memory；
- budget-matched CaRE-inspired bi-level routing；
- flat content routing；
- proposed signed Top-2 basis memory；
- proposed bounded damage-aware allocate-or-write。

### 外部强 baseline

- L2P；
- DualPrompt；
- CODA-Prompt；
- EASE；
- MOS；
- CaRE；
- 资源允许时再加入 APER、TUNA、MIN、SEMA、MoAL、MoE-Adapters++。

不同协议的论文数字不能直接拼成一张“我们的模型更优”表。

## 实验顺序

### Phase 0：CPU smoke test

仅使用 synthetic tensors 验证：

- tensor shape；
- forward/backward finite；
- router 和 memory 有非零梯度；
- Top-2 确实只激活两个 bases；
- erase/add 不超过边界；
- allocation 不超过容量；
- rejected write 能完整回滚；
- 参数量和解析 FLOPs 计算正确。

这一步不能报告 accuracy、forgetting 或任何方法优劣。

### Phase 1：最小真实实验

- 数据：Split CIFAR-100，10 tasks；
- backbone：真实预训练 ViT，冻结 backbone；
- 推理：task-agnostic；
- 先比较 calibrated no-memory、hard Top-K、dense softmax、append-only、
  allocate-then-freeze 和 signed basis memory；
- 单 seed 调试后至少 3 seeds；
- 固定 class orders；
- 匹配存储参数量（建议误差不超过 2%）和 active FLOPs（建议误差不超过 5%）。

只有 basis memory 在这个阶段形成稳定优势，才实现 damage-aware writing。

### Phase 2：写入与路由归因

- memory 在第5个 task 左右强制饱和；
- 比较 novelty、damage、nearest、freeze 和 no-write；
- 分开冻结 router / memory，区分 retrieval forgetting 与 content forgetting；
- 报告 route switch、slot drift、write rejection、collision、dead slots。

### Phase 3：扩展

- CIFAR-100 20 tasks 和至少3种 class orders；
- ImageNet-R；
- 最后才进入 OmniBenchmark-1K 100-task；
- 仅保留前两阶段通过预注册门槛的最多两个候选。

## 当前不能声称的内容

- 不能声称 novelty score 为 1.0 或已经证明创新性；自动 novelty 查询存在解析缺陷。
- 不能声称本机有 RTX 6000 Ada；当前环境没有检测到 GPU。
- 不能声称已完成真实 ViT/CIFAR-100 实验。
- 不能把 CPU synthetic smoke test 当作科研结果。
- 不能声称 writable memory 一定优于冻结或 append-only memory。
