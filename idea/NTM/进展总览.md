## 1. 研究目标

参考 CaRE（`2602.03473v2.pdf`），研究一种用于冻结 ViT 的固定容量、连续可微专家记忆：
以少量低秩 adapter bases 作为 memory slots，通过内容寻址按样本读取和组合历史能力，
再逐步研究 NTM 式 allocate / write / no-write 是否能在容量受限的持续学习中安全复用旧槽。

当前不预设“可写记忆一定优于冻结专家”。研究必须分别验证：

1. 连续、稀疏的 basis composition 是否优于 hard routing 和 dense softmax mixture；
2. 修改旧 memory slot 是否优于 append-only、allocate-then-freeze 和 no-write。

## 2. 当前收敛方向

### 阶段 A：Signed Top-2 Basis Memory

第一版只做固定容量读取，不做 erase/add 写入。在选定 ViT blocks 中保存低秩
`(key, A, B)` bases，由输入产生 query，以 signed sparse Top-2 权重组合 adapter 更新。

核心设计原则：

- task-agnostic inference，不使用测试 task ID；
- memory 容量固定，不随任务数线性增长；
- backbone 冻结；
- 与 hard Top-K、dense mixture、CaRE 做参数量和 active FLOPs 匹配；
- 先验证读取机制，再引入写入，避免无法归因。

### 阶段 B：Bounded Damage-Aware Allocate-or-Write

只有阶段 A 达到预注册门槛后才实现。writer 在 allocate、write、no-write 间决策，
用旧类 prototype 或 gradient sketch 估计候选写入损伤，并限制 erase、add norm、
累计 slot drift；越界、NaN 或高风险写入必须拒绝并回滚。

## 7. 预注册门槛

进入可写 memory 前，read-only basis 方法至少需要：

- forward/backward 全部 finite；
- 每个启用层严格只激活 Top-2 bases；
- query、keys、A、B 均获得非零且有限梯度；
- 参数量匹配误差不超过 2%；
- active FLOPs 匹配误差不超过 5%；
- CIFAR-100 单 seed 不出现明显训练退化或路由塌缩；
- 与 hard Top-K、dense mixture 的差异可归因，而非分类器或 task-ID 泄漏。

## 8. 当前已知风险与潜在卡点

- signed Top-K 的符号、归一化和稀疏梯度可能导致不稳定；
- 固定 basis 可能只相当于普通 adapter factorization，创新性必须靠容量饱和实验验证；
- 无 replay 时 writable old slots 可能不可避免地污染旧知识；
- CaRE 官方代码与新 timm/PyTorch、双 GPU 不完全兼容；
- 完整 10-task × 多 baseline × 3 seeds 需要较长 GPU 时间；
- Stage 10 若没有严格提示词约束，容易再次扩张范围；
- 任何论文结论都必须来自成功执行且可追溯的真实实验。

## 10. CaRE 工程桥接实现

更新时间：2026-07-20 00:42（Asia/Shanghai）

已在 `external/CaRE` 中手动实现最小机制层：

- `backbone/basis_memory.py`：固定容量 `BasisMemoryAdapter`；
- `signed_top2`：按绝对 cosine score 选两个 basis，保留符号并按绝对值归一化；
- `hard_top2`：按 cosine score 选两个 basis，局部 softmax；
- `dense_softmax`：对全部 basis 做 softmax mixture；
- `vit_brmoe.py`：通过 `memory_mode` 在原 CaRE MoE 与 basis memory 间切换；
- `utils/inc_net.py`：传入 basis 数、rank、key dimension 和温度；
- `tests/test_basis_memory.py`：结构、梯度、稀疏性、容量和 FLOPs 测试；
- 三份双任务 smoke 配置位于 `exps/cifar100/`。

这里的“read-only”准确含义是：本阶段没有 NTM erase/add、allocation 或 occupied-slot
writer；basis bank 容量和形状固定。basis 仍通过普通任务损失学习，否则随机固定 basis
只能退化成 router/classifier over arbitrary projections，不能检验可学习 basis memory。

### 已通过的工程验证

- 4/4 CPU 单元测试通过；
- ViT-B/16-IN21K 完整 12-layer 单批次 forward/backward 通过；
- 每层 Signed/Hard 严格激活 2 个 basis；
- `keys/down/up` 均有有限非零梯度；
- task 递增时 basis 参数量和 tensor shape 不增长，只增加 CaRE 所需辅助分类头；

- sparse 实现已改为先寻址再 gather，仅执行两个 basis；早期“计算全部 8 个再 mask”

- Signed rank-16 与 Dense rank-4 的解析 active adapter FLOPs 相等：
  batch 32、197 tokens 时均为 `619,773,952` FLOPs/层；
- A800 微基准中 Signed 约 0.753 ms/层、Dense 约 0.533 ms/层，说明相同 FLOPs
  不等于相同延迟，稀疏 gather 有额外开销。

## 13. 当前保留方法：Content-Addressed Hard Top-2 Basis Memory

更新时间：2026-07-20 02:45（Asia/Shanghai）

### 方法雏形

当前保留版本为：

- 冻结 ViT-B/16-IN21K；
- 每层固定 8 个 `(key, down, up)` basis slots；
- 每个 basis rank 16；
- 由样本 CLS token 生成 query，以 cosine 内容寻址；
- 严格 Hard Top-2，只执行被选中的两个 basis；
- Top-2 局部 softmax，temperature 0.2；
- basis residual scale 初始化为 0.1；
- 无 shared adapter、无全局负载均衡、无 task-ID 推理、无 writer；
- 容量不随任务数增长。
