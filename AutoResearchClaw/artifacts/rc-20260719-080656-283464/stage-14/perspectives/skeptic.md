[thinking] **Assessing algebraic averaging methods**
## 总体判断

现有结果只能证明实现可运行，并为后续实验筛选配置；不能证明 basis memory 有效、Signed 优于 Hard、稀疏优于 dense，也不能证明负载均衡揭示了普遍的“专门化—利用率冲突”。

`scale=0.1` 的改善值得继续验证，但目前也可能只是单个 seed、单个类别顺序和极短训练预算上的超参数拟合。所谓“与 CaRE 差距缩至 1.50 点”是描述性观察，不是统计结论。

## 1. 统计有效性不足

### 样本量实际上是 n=1

所有结果只有：

- 1 个随机 seed；
- 1 个类别顺序；
- 1 次 50+50 划分；
- 每阶段仅训练 1 epoch。

因此无法估计均值方差、置信区间或效应量的不确定性。0.60 点的 Hard–Signed 差异、0.375 点的 sparse–dense 差异以及 Signed 相对 CaRE 的 0.06 点遗忘差异，都很可能小于训练随机性和类别顺序造成的波动。

即使 Hard 相对原尺度提升了 3.89 点，也不能排除运行间随机差异，除非原尺度与 `scale=0.1` 使用严格配对的随机初始化、数据顺序、增强随机数和训练过程，并在多个 seed 上重复。

### 两阶段平均准确率信息量有限

这里的平均准确率只是两个评价时点的平均值。例如 Hard `scale=0.1`：

\[
(91.22+88.89)/2=90.055.
\]

它不是大量独立观测的平均值，而是两个高度相关时点的算术平均。因此，90.055 的三位小数制造了超过实验分辨率的精确感。报告为 90.06 尚可，但在正式比较中应提供跨 seed 和跨类别顺序的均值、标准差及置信区间。

### 存在多重比较和选择偏差

已经观察了原尺度、`scale=0.1`、Hard、Signed、dense，以及两个负载均衡权重。若 `scale=0.1` 是查看同一验证或测试结果后选出的，90.055 就是经过选择的最大值，存在 winner’s curse。

需要明确：

- scale 候选总数及选择依据；
- 是否使用测试集调参；
- 所有失败或发散配置的完整数量；
- 主要指标和主要比较是否预先指定。

若继续探索多个 scale、温度和均衡权重，应使用独立验证协议，并对最终预注册比较进行确认性测试。否则不宜报告显著性检验；即使报告，也需控制 family-wise error 或 false discovery rate。

## 2. 关键混杂因素与替代解释

### `scale=0.1` 改善未必来自 basis memory

缩小 adapter 残差可能只是让模型更接近冻结的强预训练 ViT。性能提高可能意味着“少干预 backbone 更好”，而不是 basis 表达或内容寻址有效。

缺失的关键对照包括：

- 完全关闭 adapter，即 `scale=0`；
- 不同 scale 的普通单 adapter；
- 随机或固定 Top-2 路由；
- 不学习 basis、只学习路由，以及只学习 basis、固定路由；
- 与 basis 参数量匹配的低秩非记忆 adapter。

如果 `scale=0` 或普通 adapter 已接近 90%，当前结果不能归因于 memory。

### Hard 与 Signed 的比较可能并不隔离“符号”

必须确认两者是否具有相同初始化、归一化、温度、Top-2 选择、系数幅值和梯度路径。Signed 的负系数可能改变有效残差范数，使其隐式拥有不同的 scale。应报告每层 adapter 输出范数、正负权重比例、有效秩和梯度范数；否则 0.60 点差异无法解释为签名组合机制的效果。

### sparse 与 dense 并非公平对照

当前 sparse 使用 rank 16，dense 使用 rank 4。两者只匹配了分析 active FLOPs，却没有匹配：

- 存储参数量；
- 表达秩；
- 优化参数数量；
- 实际延迟；
- 内存访问量；
- 峰值显存。

而实测 sparse 为 0.753 ms、dense 为 0.533 ms，sparse 慢约 41%。因此当前数据既不能支持“稀疏更高效”，也不能将准确率差异归因于稀疏读取本身。

### CaRE 对照的训练公平性尚未建立

需要确认 CaRE 与 basis 条件是否完全共享：

- 预训练权重及其版本；
- 数据增强和数据顺序；
- 优化器、学习率及调度；
- classifier 更新和校准方式；
- 可训练层、训练 epoch、batch size；
- 参数预算、初始化和 checkpoint 选择规则。

CaRE 第一阶段比最佳 Hard 高 2.18 点，而最终仅高 0.81 点。这可能说明 basis 的主要缺陷是欠拟合或优化速度较慢，而不是持续学习能力不同。但在 1 epoch 条件下，无法区分优化速度与最终性能。

### 负载均衡结果有多种解释

均衡项使准确率下降并不自动证明“专门化—容量利用冲突”。替代解释包括：

- 正则权重相对于主损失过大；
- loss 尺度或归一化错误；
- batch-level usage 是全局 usage 的有偏估计；
- 强制使用质量较差或尚未训练成熟的槽；
- 路由变化导致训练—推理分布不一致；
- 均衡项降低 adapter 输出幅值或改变梯度规模。

“消除大多数 dead slots”也不够精确。需要预定义 dead-slot 阈值，并报告使用率分布、熵、Gini 系数、每槽样本量、跨阶段稳定性及置信区间。

## 3. 缺失的证据和必要控制

最低限度的确认性实验应包括：

1. 至少 3–5 个 seed，并使用多个固定类别顺序；最好将 seed 与类别顺序分开分析。
2. 与 CaRE 一致的充分训练预算，并报告学习曲线，而非只比较 1 epoch 终点。
3. `scale=0`、普通 adapter、随机 Top-2、固定 Top-2和无记忆低秩 adapter 对照。
4. Hard 与 Signed 的严格配对运行，以及 adapter 输出范数匹配。
5. dense/sparse 的两套公平比较：
   - 等存储参数、近似等表达容量；
   - 等实测延迟或吞吐量。
6. 每阶段旧类和新类准确率，避免总体准确率掩盖稳定性—可塑性权衡。
7. 路由诊断：slot occupancy、路由熵、切换率、类别/任务纯度、dead slots、跨阶段漂移。
8. 固定容量真正受压的长序列实验。50+50 两阶段不足以检验容量饱和、长期路由误差或非线性容量增长。
9. conventional、不同类别顺序以及 interleaved/boundary-free streams；当前协议不能支持关于真正 task-agnostic 长序列学习的外推。
10. 对 shared+basis 发散给出发生率和诊断，而非仅排除失败运行。若多个候选配置发散，稳定性本身就是方法成本。

## 4. 指标是否测到了目标现象

### Average accuracy 不能单独证明记忆有效

准确率混合了表征质量、分类器偏差、路由质量和遗忘。没有 frozen-ViT/calibrated classifier 基线，就不知道 memory 增加了什么。

### Forgetting 可能被低初始学习掩盖

负载均衡权重 0.1 的遗忘只有 1.00，但其 task-0 准确率仅为 88.52，明显低于 CaRE 的 93.4。较低的初始峰值天然留下较少“可遗忘”的空间。因此，低 forgetting 可能是欠学习，而非记忆保持更强。

应同时报告：

- 每任务学习后的峰值准确率；
- 最终旧类准确率；
- BWT；
- 新类学习准确率或 intransigence；
- stability–plasticity 曲线。

### 两任务无法检验“固定容量”

容量固定是实现属性，不等于固定容量在持续学习中有效。只有当任务数持续增加、槽容量逐步饱和时，才能评估知识复用、槽坍缩、覆盖风险和容量—性能曲线。

### task-agnostic 标签不足以证明路由鲁棒

没有 task ID 只是协议条件。还需测量路由错误、类别条件路由、一致性以及边界附近行为。当前干净的 50+50 阶段流也不等同于真正 boundary-free 或 interleaved continual learning。

## 结论

目前唯一稳健的结论是：该实现通过了必要工程检查，并且 `scale` 是高度敏感的关键超参数。以下说法均尚未获得证据支持：

- basis memory 接近或优于 CaRE；
- Signed 具有更好的抗遗忘能力；
- sparse Top-2 优于 dense composition；
- 负载均衡揭示了普遍的专门化—利用率冲突；
- 固定容量 memory 能处理长序列持续学习。

下一轮应优先做充分训练、严格配对的多 seed/多类别顺序验证，并补齐 `scale=0` 和非记忆 adapter 对照。若这些检查后 Hard `scale=0.1` 的优势仍存在，再研究温和防塌缩或 task-transition stabilization。当前没有足够依据进入 bounded writer；那会增加混杂因素，使尚未确认的 read-only 效果更难解释。
